# 案例：一支 AI MV 的七轮试剪和一次 A/B 对比

下面是这个 skill 第一次实际使用时的经过，供判断参考。数字和结论只对那一首歌成立。

## 两种剪法的对比

一次实测的结果，供参考：

| | A 版（被选中） | B 版 |
|---|---|---|
| 参考片 | 运动番 OP 式快切 | 日常番 OP 式定格 |
| 剪法 | 切得碎（39 刀），换段落白闪，竖框画中画，钩子上砸大字卡 | 刀少，主歌拍上定格 0.7 秒压彩色手写署名，甩镜转场，片名砸入再甩走，跳级拉远，颜料滴落进副歌，同机位推近，单色段，照片版式结尾 |
| 署名 | 片尾黑底字幕 | 只在定格卡上 |

用户看完 B 版说“有那个味了”，但最后还是选了 A 版。这只是一首轻快电子歌上的一次选择；没有新参考片时可以从 A 式起步，换了风格差别大的歌，仍值得做对比让用户挑。两版都先做对、再让用户比，比出来的才是剪法偏好，而不是哪版没做好。

## 当时踩过的坑

- **不要把 loudnorm 放进视频滤镜图**：动态模式曾在 AAC 时间戳里留下 0.68–3.67 秒的空洞，第一句歌词没了（“第一句歌词的音频有问题，没有唱全”），开头还比结尾多抬约 3 dB。`render_edl.py` 已改成先单独渲 WAV、整体增益加限幅。
- **whisper 不要用 token offsets**：用 offsets 时第一句提前 0.8 秒、句中常差一个字（“有的时候对上了，有的时候慢半拍”）；DTW 两个模型中位差 0.02 秒，和人声频段能量的起点对得上。`-dtw` 必须配 `-nfa`，否则 flash attention 让 DTW 静默失效，`t_dtw` 全是 −1。哼唱 whisper 听不出，用 `--spread` 均分，标 guessed。
- **起音点检验太松**：混音里每秒七八个 onset，任何时间附近都有一个，不能拿来证明唱点对。要么两个模型交叉核对，要么看人声频段（300–3500 Hz、谐波部分）的能量起点逐个数音节。
- **Pillow 贴图**：`alpha_composite` 不接受负坐标和出界，用 `render_edl.py` 的 `paste_rgba`。
- **改了共用参数要整条重渲**：比如字幕字号同时影响正片里的歌名卡，只重渲片尾会让剪辑表和片子对不上。
- **抽帧只看 1 秒一格**：第二支参考片第一次只看了 1 秒一格的抽帧图，学到的只是「几段变黄」，被指出“没有 copy 到精髓”。之后改成全片 0.1–0.125 秒一格密抽、逐个刀口写转场清单。
- **照搬参考片的颜色**：单色段照搬了参考片的黄色，在蓝白画面上很怪。之后改成用本片主色。

## 后来修掉的工具问题

这些是事后审查发现、已在工具里修掉的问题，记在这里以免回退：工作目录写成 `tmp/..` 会删掉项目；`-ss` 只保留四位小数导致抽错帧；VFR 视频按名义帧率换算漏帧；AVOID 区间有 20 ms 放行；倒放带进多读的 0.1 秒；定格在部分 FFmpeg 版本只出 1 帧；限幅器不开延迟补偿会让 PCM 晚约 5 ms；歌词让位会改掉所有相同的句子。对应的回归测试见 `tests/run_tests.py`（T01–T27）。
